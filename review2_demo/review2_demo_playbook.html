1 · Before you start
Warm the model up before you walk in. The first query after streamlit run ui/app.py loads Sentence-BERT, the NLI cross-encoder, and BERTScore into memory, then waits on Ollama — that can take 30–60 seconds. Run every demo question once, privately, before the panel arrives. During the live demo, repeat queries respond in a few seconds.

3 · If something breaks
Ollama silent

No response after ~90s

Open a terminal, run ollama serve, then re-ask the same question. The app falls back to a clearly labeled extractive answer automatically, so it never crashes — but a restart usually fixes it before anyone notices.

Model missing

"Model may not be pulled" warning

Run ollama pull mistral (or whichever model config.yaml names) in a terminal. Do this the night before, not live.

Port busy

Streamlit won't launch

streamlit run ui/app.py --server.port 8502 and open that port instead.

Total failure

Nothing loads at all

Open the Browser Backup chat artifact instead — same real 82-chunk corpus and the same 0.45/0.35/0.20 scoring formula, running entirely client-side with no Ollama, Python, or install needed.

4 · Anticipated panel Q&A
What are your evaluation numbers — Precision, Recall, F1?
We've verified the full pipeline end-to-end with a control-logic sanity check confirming the tri-state classification and metric computation are wired correctly. Full-scale evaluation against a properly annotated test set, plus the MS MARCO merge, is the planned next step for Semester 3 — we're not presenting inflated preliminary numbers before the models have actually been exercised at scale.
Why these weights — 0.45 NLI, 0.35 BERTScore, 0.20 Cosine?
NLI entailment most directly tests logical support, so it carries the most weight; BERTScore adds semantic-overlap robustness where entailment models can be brittle; cosine similarity is the lightest signal since it only checks topical relevance, not logical support.
Why local models instead of GPT-4 or another cloud API?
The core design goal is offline, privacy-preserving operation with no data leaving the machine — a hospital, law firm, or defense context often can't send documents to a cloud API at all. Local models trade some raw fluency for that guarantee.
What happens if the retrieved evidence is simply wrong or outdated?
The system can only verify internal consistency between the answer and what was retrieved — it isn't a fact-checker against ground truth in the world. That's a known limitation of evidence-attribution approaches generally, not unique to this system.
How is this different from just asking the LLM to "cite your sources"?
Self-reported citations from an LLM can themselves be hallucinated. Here, attribution and scoring happen in a separate verification layer using independent models (NLI, BERTScore, cosine) that never generated the answer, so a confident-sounding fabrication can still be caught.
