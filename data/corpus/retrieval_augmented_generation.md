# Retrieval-Augmented Generation (RAG)

Retrieval-Augmented Generation, or RAG, is an architecture for building language-model systems that combines two separate capabilities: a retriever that searches an external knowledge source, and a generator that produces natural-language text. Instead of relying only on facts memorized during training, a RAG system looks up relevant passages from a document collection at query time and feeds them to the language model as context before it writes an answer.

The typical RAG pipeline has three stages. First, documents are split into smaller chunks and converted into vector embeddings using an embedding model, then stored in a vector index. Second, when a user asks a question, the same embedding model converts the query into a vector, and the index returns the most similar chunks by a distance or similarity measure such as cosine similarity. Third, the retrieved chunks are inserted into a prompt along with the original question, and a large language model generates an answer conditioned on that retrieved evidence.

The main motivation for RAG is grounding: a language model trained purely on its pretraining data can produce fluent but factually incorrect statements, a failure mode generally called hallucination. By forcing the model to base its answer on retrieved, verifiable text, RAG reduces (though does not eliminate) this risk, and it also makes answers auditable, since the system can cite exactly which document a claim came from. RAG additionally allows a system to stay current and domain-specific without retraining the underlying model — updating the knowledge base is as simple as re-indexing new documents.

RAG systems can run entirely offline when every component — the embedding model, the vector index, and the generator — is hosted locally rather than through a cloud API. This is attractive for privacy-sensitive or air-gapped deployments, such as legal, medical, or defense settings, where documents cannot leave the organization's own infrastructure. Running offline typically means smaller, quantized open-weight models (served through a runtime such as Ollama) rather than very large proprietary models, trading some generation fluency for data privacy and zero marginal API cost.

RAG is not a guarantee against hallucination by itself. A language model can still ignore the retrieved context, misread it, or generate a claim not actually supported by any retrieved chunk — sometimes called "RAG hallucination" to distinguish it from hallucination caused purely by a model's own parametric knowledge. This is precisely the gap that hallucination-detection layers, such as entailment classifiers or similarity-based verification, are designed to catch: they check, after generation, whether each sentence in the answer is actually backed by the evidence that was retrieved for it, rather than simply trusting that retrieval plus generation together produced a faithful response.
