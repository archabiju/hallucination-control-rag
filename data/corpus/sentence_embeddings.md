# Sentence Embeddings and Semantic Search

A sentence embedding is a fixed-length numeric vector that represents the meaning of a piece of text, produced by a neural network trained so that texts with similar meaning end up close together in the resulting vector space, while unrelated texts end up far apart. Unlike older bag-of-words representations, which only capture which words appear, embeddings capture semantic similarity — two sentences phrased completely differently but meaning the same thing will still have vectors that point in nearly the same direction.

The Sentence-BERT family of models, including all-MiniLM-L6-v2, is one of the most widely used approaches for producing these embeddings efficiently. It fine-tunes a transformer encoder (a distilled, smaller version of BERT-style architectures) using a contrastive or similarity-based training objective, so that encoding a sentence takes a single forward pass rather than the pairwise comparisons earlier BERT-based similarity methods required. all-MiniLM-L6-v2 specifically produces 384-dimensional vectors, is only about 80 megabytes, and runs comfortably on a CPU, which makes it a practical default for offline or resource-constrained retrieval systems rather than requiring a GPU or a cloud embedding API.

Once documents and queries are both converted into this shared vector space, semantic search becomes a nearest-neighbor problem: given a query vector, find the document vectors closest to it. Closeness is usually measured with cosine similarity, which looks only at the angle between two vectors and ignores their magnitude, or with the dot product when vectors are first normalized to unit length (in which case the two measures become equivalent). This is why retrieval pipelines typically normalize embeddings before indexing — it lets a fast dot-product search stand in for cosine similarity without extra computation at query time.

Semantic search improves substantially on older keyword-matching search because it can retrieve a relevant passage even when the query and the passage share almost no exact words — for example, a query about "how to reduce fabricated answers" can retrieve a passage about "hallucination mitigation techniques" even without a single overlapping keyword, because the two phrases are embedded close together. This property is what makes sentence embeddings the standard first stage of a modern retrieval-augmented generation pipeline: they decide which chunks of a document collection are even considered before the language model sees anything.
