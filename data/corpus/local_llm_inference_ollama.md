# Large Language Models and Local Inference with Ollama

A large language model (LLM) is a neural network, almost always based on the transformer architecture, trained on very large amounts of text to predict the next token in a sequence. At sufficient scale, this simple training objective gives rise to broad capabilities: answering questions, summarizing, translating, and following instructions, even though the model was never explicitly trained to do any one of those tasks directly. Well-known LLM families include the proprietary GPT models accessed through an API, and open-weight models such as Meta's LLaMA family and Mistral AI's Mistral models, whose weights can be downloaded and run on a user's own hardware rather than only through a cloud provider.

Running an LLM "locally" means the model's weights are loaded and the forward pass is computed on the user's own machine rather than sent to a remote server. Ollama is a tool that makes this practical for non-specialist users: it packages open-weight models (Mistral, LLaMA 3, Phi-3, and many others) into a single downloadable artifact, handles quantization (compressing the model's numeric weights to use less memory, typically with only a small accuracy cost), and exposes a simple local HTTP API — by default at http://localhost:11434 — so that any application can send a prompt and receive a generated completion with a single request, without the application needing to know anything about how the model itself is loaded or run.

Local inference has direct consequences for how a retrieval-augmented system can be deployed. Because no data leaves the machine, it is suitable for privacy-sensitive or regulated environments where sending documents to a third-party API would be unacceptable. There is no per-token or per-request cost, no rate limit imposed by an external provider, and no dependency on network connectivity, which matters for genuinely offline deployments. The trade-off is hardware: open-weight models run through Ollama are typically smaller than the largest proprietary models, and inference speed depends entirely on the local machine's CPU or GPU, so a response that takes a fraction of a second from a well-provisioned cloud API might take tens of seconds on a laptop, especially the first time a model is loaded into memory.

For a hallucination-controlled RAG system, the choice of local generator interacts directly with the detection layer: the LLM generator is explicitly instructed, via its system prompt, to answer only from the retrieved context and to say so explicitly when the context is insufficient — but this instruction is a request, not a guarantee, which is exactly why a separate, independent verification step (checking the generated answer against the evidence after the fact, rather than only trusting the prompt) remains necessary even when the generator has been told to behave conservatively.
